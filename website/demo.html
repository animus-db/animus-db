A cluster in this tab

This page runs the real AnimusDB request path (the DynamoDB-compatible edge, the Raft control plane and a Raft group per tablet) compiled to WebAssembly, on the same deterministic simulator the project's tests use. Create a table, write and read items, then crash a node or cut the network and watch the cluster recover. The same cluster also serves the real data console and operator dashboard, in tabs below.

What this is, and is not

What is real

  • The DynamoDB JSON request path, from request parsing to the item and table operations, is the same code the server runs.
  • Each node runs a multi-voter control-plane Raft group, and every tablet replica runs its own Raft group. Elections, replication and leader changes all happen.
  • Crashing a node keeps its state for the restart; a partition drops the messages between two nodes.

What is simulated

  • Time is virtual. The cluster's clock only moves while this tab is visible and not paused, at the speed you pick. A background tab pauses it instead of letting elections flap.
  • Everything is in memory. There are no sockets, threads or disk. Reloading the page discards the cluster.
  • Seeded. The same seed builds the same cluster, and the cluster is a pure function of the calls made on it. Your clicks and frame timing are real, so a hand-driven session will not replay byte for byte.

Not available here: on-demand backup, PITR restore, table export and import, tagging, and adding or removing a global secondary index or a stream with UpdateTable. Those requests answer with an "unsupported" error, in the DynamoDB requests and in the web UIs alike (so the data console's index changes and the dashboard's Backups view report errors). This is a demonstration, not a benchmark: the numbers it shows are virtual milliseconds, not performance.

    Talk to the cluster

    Three ways in, all against the same cluster: raw DynamoDB requests, the data console (the tables-and-items web UI animusd serves on its console port), and the operator dashboard (the cluster-state UI on its admin port). The two web UIs here are the real files from the repository, running unmodified in this tab; their HTTP calls are answered by the in-browser cluster.

    Browse tables and items, create or change a table, turn on a stream or TTL. A table you created in the request tab shows up here, and the reverse.

    Overview, placement, tablets, transactions, streams, data browser and storage debug views. Crash a node above and refresh. Backups need an object store and the metrics exporter needs a collector; neither exists in a tab, so those views show an empty or error state.

    Pick an example, edit the JSON if you like, and send it to any node. The request is a DynamoDB JSON body; the target is the X-Amz-Target operation it would carry over HTTP. A request to a crashed node is refused with 503, and a request that gets no answer in 30 virtual seconds returns 504. The examples run in order: start with CreateTable.
