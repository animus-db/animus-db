A real AnimusDB cluster, running in this tab on virtual time. Send DynamoDB requests, browse the data, crash a node or cut the network, and watch Raft recover.

What’s real here

What is real

  • The DynamoDB JSON request path, from request parsing to the item and table operations, is the same code the server runs.
  • Each node runs a multi-voter control-plane Raft group, and every tablet replica runs its own Raft group. Elections, replication and leader changes all happen.
  • The data console and the operator dashboard are the real animusd web UIs, unmodified apart from an embedded mode that hides their own header; their HTTP calls are answered by the in-tab cluster.
  • Crashing a node keeps its state for the restart; a partition drops the messages between two nodes.

What is simulated

  • Time is virtual. The cluster’s clock only moves while this tab is visible and not paused, at the speed you pick. A background tab pauses it instead of letting elections flap.
  • Everything is in memory. There are no sockets, threads or disk. Reloading the page discards the cluster.
  • Seeded. The same seed builds the same cluster, and the cluster is a pure function of the calls made on it. Your clicks and frame timing are real, so a hand-driven session will not replay byte for byte.

Not available here

On-demand backup, PITR restore, table export and import, tagging, and adding or removing a global secondary index or a stream with UpdateTable. Those requests answer with an “unsupported” error, in the Requests view and in the web UIs alike (so the data console’s index changes and the dashboard’s Backups view report errors). The dashboard’s metrics exporter and peer-console links need things a tab does not have.

This is a demonstration, not a benchmark: the numbers it shows are virtual milliseconds, not performance.

A cluster in this tab

Pick a size and a seed, then start. The first start downloads the WebAssembly build of the real request path.

Downloads about 1.7 MB (compressed) of WebAssembly on first start.

Pick an example, edit the JSON if you like, and send it to any node. The request is a DynamoDB JSON body; the target is the X-Amz-Target operation it would carry over HTTP. A request to a crashed node is refused with 503, and a request that gets no answer in 30 virtual seconds returns 504. The examples run in order: start with CreateTable.
