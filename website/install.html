Install

Get a cluster running

AnimusDB builds from source with Cargo. There are no packages or container images yet — clone, build, run. About a minute of typing plus a compile.

Prerequisites

A Rust toolchain and Git. The repository pins its toolchain, so rustup will fetch the right compiler automatically the first time you build.

  • Rust 1.96 or newer — install with rustup.
  • Git, and a machine with a few gigabytes free for the build.
  • Linux or macOS. Windows is untested.

Optional, for talking to the database once it's up:

  • The AWS CLI or any AWS SDK, for the DynamoDB endpoint.

Build from source

build
$ git clone https://github.com/animus-db/animus-db.git
$ cd animus-db
$ cargo build --release

That produces two binaries in target/release:

BinaryWhat it is
animusdThe node server. One process per node; it hosts the control plane, the data plane and every wire endpoint.
animusThe operator and client CLI — cluster status, simple get/put, and the whole admin subcommand tree.

A debug build (cargo build) is fine for experimenting and compiles faster, but is markedly slower at runtime. Use --release for anything you intend to measure.

Run a cluster

The fastest way to see AnimusDB work is a whole cluster in one process. Nodes bind OS-assigned ports and print them at startup.

three nodes, one process
$ ./target/release/animusd --cluster 3
animusd: started 3-node cluster (CP)
  node 0: client 127.0.0.1:52104 — dynamo http 127.0.0.1:52105
          — admin http://127.0.0.1:52107 — console http://127.0.0.1:52109
  node 1: client 127.0.0.1:52111 — dynamo http 127.0.0.1:52112 …
  node 2: client 127.0.0.1:52118 — dynamo http 127.0.0.1:52119 …
animusd: ready — Ctrl-C to stop
Keep the data, or don't

State is written under a temporary directory by default. Pass --dir ./cluster-data to keep it somewhere you choose, or --ephemeral to keep everything in memory and discard it on exit.

Add --auto-split-bytes 67108864 to watch tablets split as they grow, which is the interesting behaviour to poke at on a laptop.

Connect to it

Any node accepts any request and routes it internally, so you can talk to whichever one you like. The examples below use node 0's printed dynamo port.

The AWS CLI

SigV4 signature verification is opt-in and off by default, but the AWS CLI insists on credentials being present regardless — any placeholder values work unless you've turned verification on.

aws cli
$ export AWS_ACCESS_KEY_ID=local AWS_SECRET_ACCESS_KEY=local AWS_REGION=us-east-1
$ export ANIMUS=http://127.0.0.1:52105

$ aws dynamodb create-table --endpoint-url $ANIMUS \
    --table-name orders \
    --attribute-definitions AttributeName=id,AttributeType=S \
    --key-schema AttributeName=id,KeyType=HASH \
    --billing-mode PAY_PER_REQUEST

$ aws dynamodb put-item --endpoint-url $ANIMUS --table-name orders \
    --item '{"id": {"S": "a-1"}, "total": {"N": "42"}}'

$ aws dynamodb get-item --endpoint-url $ANIMUS --table-name orders \
    --key '{"id": {"S": "a-1"}}'
{ "Item": { "id": { "S": "a-1" }, "total": { "N": "42" } } }

Python (boto3)

boto3
import boto3

db = boto3.resource(
    "dynamodb",
    endpoint_url="http://127.0.0.1:52105",
    region_name="us-east-1",
    aws_access_key_id="local",
    aws_secret_access_key="local",
)

table = db.Table("orders")
table.put_item(Item={"id": "a-2", "total": 99})
print(table.get_item(Key={"id": "a-2"})["Item"])

JavaScript (AWS SDK v3)

@aws-sdk/client-dynamodb
import { DynamoDBClient, PutItemCommand } from "@aws-sdk/client-dynamodb";

const client = new DynamoDBClient({
  endpoint: "http://127.0.0.1:52105",
  region: "us-east-1",
  credentials: { accessKeyId: "local", secretAccessKey: "local" },
});

await client.send(new PutItemCommand({
  TableName: "orders",
  Item: { id: { S: "a-3" }, total: { N: "7" } },
}));

The animus CLI

animus
# cluster status, against a node's client port
$ ./target/release/animus status 127.0.0.1:52104

# raw key/value access, against a table
$ ./target/release/animus put 127.0.0.1:52104 orders k1 hello
$ ./target/release/animus get 127.0.0.1:52104 orders k1

# operator surface, against a node's admin port
$ ./target/release/animus admin status 127.0.0.1:52107

Open the consoles

Two web UIs are compiled into animusd; neither needs a build step or an internet connection.

Operator dashboard

On the admin port. Cluster and node health, the tablet map, Raft internals, storage and WAL introspection, and gated operator actions like split, flush, drain and decommission.

Data console

On the console port. A DynamoDB-shaped app for application developers: browse tables, inspect and edit items, review a table's configuration and its stream.

Both are printed in the startup banner. Neither has authentication — see the security note. (SigV4 verification, when enabled, applies only to the DynamoDB client port.)

Run a real multi-node cluster

For separate machines, generate a config once, copy it to every node, and start one process per node with a distinct --node index.

  1. Generate a cluster config

    on any machine
    $ animusd gen-config --nodes 3 --host 10.0.0.1 > cluster.json

    The generated config lists every node's identity and its seven listener addresses. Edit the hosts so each entry names the right machine, then copy the same file to all of them. Ports start at --base-port (7100 by default).

  2. Start each node

    one per machine
    # on the first machine
$ animusd --config cluster.json --node 0 --dir /var/lib/animusdb

# on the second, and so on
$ animusd --config cluster.json --node 1 --dir /var/lib/animusdb
$ animusd --config cluster.json --node 2 --dir /var/lib/animusdb

  3. Check it came up

    verify
    $ animus admin status 10.0.0.1:7104
$ animus admin health 10.0.0.1:7104

    Or open the dashboard at http://10.0.0.1:7104.

Add and remove nodes

A new node does not need the cluster config. Give it the intra-cluster address of any running node and it registers itself, learns the topology, and starts receiving tablet replicas.

grow
# on the new machine — 7105 is node 0's intra port
$ animusd join --seed 10.0.0.1:7105 --base-port 7100 --dir /var/lib/animusdb

Removing one is a drain followed by a decommission, so replicas move off before the node goes away:

shrink
$ animus admin drain 10.0.0.1:7104 n3
$ animus admin drain-status 10.0.0.1:7104 n3
$ animus admin decommission 10.0.0.1:7104 n3

Split control and data

Larger clusters usually want a small, stable control quorum that is not competing with storage for resources. Generate a split config and run each role explicitly.

split deployment
$ animusd gen-config --control-nodes 3 --data-nodes 5 --host 10.0.0.1 > cluster.json

# control-only: metadata quorum, no storage engine
$ animusd control --config cluster.json --node 0

# data-only: hosts tablets, mirrors metadata from the control plane
$ animusd data --config cluster.json --node 3

# or let a data node join by seed instead of by config
$ animusd data --seed 10.0.0.1:7105 --base-port 7200

To try the shape without eight machines, animusd --cluster-control 3 --cluster-data 5 runs the whole split deployment in one process.

Ports

Each node owns a block of seven consecutive ports, starting at its base port (7100 for node 0 in a generated config, then 7107, 7114, and so on).

OffsetNode 0ListenerPurposeExposure
+07100internalRaft traffic between nodesCluster-internal
+17101clientThe native length-prefixed protocol the animus CLI speaksTrusted
+27102dynamoDynamoDB JSON over HTTP, plus GET /metricsTrusted
+37103(reserved)Bound for a second wire protocol that these docs don't cover.Cluster-internal
+47104adminAdmin JSON API and the operator dashboardCluster-internal
+57105intraNode-to-node request forwarding and metadata mirroring; the address to --seedCluster-internal
+67106consoleThe data console (not bound on control-only nodes)Cluster-internal

Only the DynamoDB port can verify a caller, and only if you turn on SigV4 — off by default. Everywhere else "trusted" means a network you control. Keep the internal, reserved, intra, admin and console ports off any externally reachable address.

Common flags

FlagEffect
--config FILE --node IRun node I of a generated cluster config. The normal production invocation.
--cluster NRun an N-node cluster in a single process. Development convenience.
--dir DIRWhere this node keeps its write-ahead logs, SSTables and snapshots.
--ephemeralKeep all state in memory; nothing survives a restart.
--auto-split-bytes BSplit a tablet once it exceeds B bytes.
--quiesce-after SECSHow long a tablet group must be idle before it stops ticking. On by default.
--stream-seal-bytes B
--stream-seal-age SECS
--stream-retention SECS		When change-log segments are sealed into stream shards, and how long they are kept.
--segment-store dir:PATHStore sealed stream segments on a filesystem path instead of replicating them across the cluster.

Run animusd with no arguments for the full usage summary, and animus for the CLI's.

Data directory

Each node writes everything it owns under --dir: a write-ahead log and SSTables per hosted tablet, control-plane state, and snapshots. Nodes never share a directory — give each process its own, on storage you would be happy to lose a machine's worth of.

No migrations yet

On-disk and wire formats change between revisions without compatibility shims. When you update AnimusDB, recreate the cluster: stop the nodes, delete the data directories, and start fresh.

Troubleshooting

The build fails on an old toolchain

The workspace pins Rust 1.96. Run rustup update and build from the repository root so the pin applies.

A write returns "not leader"

Nodes forward to the tablet's leader and retry through an election, so this should be transient. If it persists, check animus admin health — a tablet with no reachable quorum cannot accept writes, by design.

Address already in use

Every node needs its own block of seven ports. In a generated config the blocks are contiguous, so two nodes on one host must be given different base ports.

The AWS SDK rejects the endpoint

Set a region and placeholder credentials — the SDKs require them even though AnimusDB doesn't check them unless SigV4 verification is switched on — and use http://, not https://. There is no TLS yet.

Something is wrong and it looks like a bug

Please open an issue. Include the animusd invocation and, if a test failed, the seed it printed — that alone is enough to replay the exact failure.
