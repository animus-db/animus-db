# ADR 0082 — Browser build: an `embedded` cluster on a virtual clock driven from JavaScript, not a real-time `WebEnv`

- **Status:** Accepted (2026-10-30), implemented the same day on branch `feat/wasm-browser-build`.
- **Date:** 2026-10-30
- **Origin:** the maintainer goal "run AnimusDB in a web browser from the project website".
- **Amends:** none. **Cross-references:** ADR 0003 (determinism, the `Env` seam), ADR 0061 (the `E: Env`-generic node brain; its 2026-10-30 amendment points here).
- **Not in scope:** persistence in the browser (IndexedDB), a real-time `WebEnv`, networking between tabs, any change to a wire or on-disk format (none is touched).

## Context

The website is documentation, and the most direct way to document a database is to let a reader use one. AnimusDB's request path is already generic over the `Env` seam (`ClientCtx<E, R>`, `dispatch_item_op`, `execute_item_op_as`; ADR 0061), and `SimCluster` (ADR 0061 rung D1) is a whole multi-node cluster on one deterministic `animus_sim::Simulator`: a real multi-voter control-plane Raft quorum, a real Raft group per tablet replica, a per-node tablet-host reconciler, and the same generic request path the production DynamoDB edge uses. Nothing in that stack needs a socket, a thread, a disk or a wall clock. What kept it from `wasm32-unknown-unknown` was only that `animusd` was one crate that also contained the real process (sockets, TLS, `ProdEnv`, OpenTelemetry, signals) and that `SimCluster` was `cfg(test)`.

## Decision

1. **Two cargo features on `animusd`.** `server` (default on) holds everything that is the real process; `embedded` compiles the `SimCluster` fixture outside `cfg(test)` and exposes it as `animusd::embedded::EmbeddedCluster`. `cargo build -p animusd` is unchanged. The split gates whole items by `#[cfg(feature = "server")]`; the generic brain is not rewritten (`docs/lessons/code-patterns/2026-10-30-gate-a-process-boundary-by-feature-not-by-rewriting-the-generic-core.md`).
2. **Embed `SimCluster`; the page drives its virtual clock.** `EmbeddedCluster` exposes `submit`/`poll`/`advance`/`crash`/`restart`/`partition`/`heal_all`/`grow`/`status`. A new crate `animus-web` (`cdylib` + `rlib`) wraps it in a plain-Rust core (the request pump, native-tested) and a thin `wasm-bindgen` shell, the JS class `AnimusCluster`. JavaScript measures real elapsed milliseconds in a `requestAnimationFrame` loop and calls `tick(realMs, speed)`; the cluster advances `realMs * speed` of **virtual** time. Real time never enters Rust.
3. **Single-threaded, in memory.** The wasm build has no threads, sockets or disk. Reloading the tab discards the cluster. Requests complete through promises settled by the pump; a request unanswered after 30 virtual seconds resolves with 504, and a request to a crashed node is refused with 503.
4. **Shipping.** `scripts/build-web-demo.sh` builds the `wasm-release` profile (`opt-level = "s"`, fat LTO), runs a `wasm-bindgen-cli` pinned to the `wasm-bindgen` version in `Cargo.lock`, and writes `website/demo/pkg/` (gitignored). `pages.yml` runs it before uploading `website/`. The wasm is loaded lazily when the visitor clicks "Start cluster". Measured 2026-10-30: 5.7 MB raw, 1.68 MB gzipped.

## Why not a real-time `WebEnv`

A `WebEnv` (an `Env` over `setTimeout`/`fetch`/`WebSocket`, so a node could be a real peer of a server cluster) is possible in principle: the generic brain is the same code. It was rejected for this goal for three reasons.

- **The `Env` contract is `Send + Sync`; JS futures are not.** `wasm-bindgen-futures` `JsFuture` is `!Send`, so an `Env` whose `sleep`/`spawn` are built on browser primitives cannot satisfy the trait bounds without unsafe `Send` wrappers (and this workspace forbids `unsafe`). Loosening the trait for all implementors would be a workspace-wide change for one consumer.
- **Browsers throttle background timers.** A tab in the background gets `setTimeout` clamped to one second or worse. Raft's election and heartbeat timers on a real clock would then flap: a leader that cannot heartbeat for seconds is deposed, and the cluster churns while nobody is looking. Virtual time simply pauses with the tab.
- **Determinism.** A virtual clock makes a run a pure function of its seed and the calls made on it (ADR 0003): bugs seen in the browser replay natively, and the demo exercises the code the project's tests exercise rather than a second environment implementation with its own timing behaviour.

## What is gated and what is not served

Gated off the browser build (`server`): `Node`/`BoundNode` and the `run_node*`/`start_cluster*` entry points, the TCP serve loops and TLS of the DynamoDB/admin/console edges, `ProdEnv`, `FsSegmentStore`, `socket2`, `tokio-rustls`, OpenTelemetry/tracing-subscriber, tokio `net`/`fs`/`signal`/`rt-multi-thread`/`time`, the `animusd` binary, and the real-store variants of the segment/backup store handles. CI asserts `socket2`, `tokio-rustls` and `opentelemetry` are absent from `animus-web`'s wasm dependency graph.

Served in the browser: item operations (including `Batch*`, `Transact*`, PartiQL), `CreateTable`/`DeleteTable`/`ListTables`/`DescribeTable`/`UpdateTable` throughput, the four DynamoDB Streams reads, and global secondary indexes (the embedded cluster runs the per-node change-consumer loop). Not served, answering the same "unsupported by generic dispatch" error `SimCluster` returns: on-demand backup, export, import, restore, tagging, and `UpdateTable` that adds or removes an index or a stream.

## Limits and risks

- **Size.** About 1.7 MB gzipped is a real download, hence the lazy load. `wasm-opt -Oz` was measured and rejected: 13% smaller raw, about 10% larger gzipped.
- **Embedded API is panic-sensitive.** A panic in the wasm instance aborts it. `EmbeddedCluster::grow` refuses (an error, not a panic) while a node is down or a partition is in place, because the fixture waits for every node to see the new member. The shell installs a panic hook that writes to `console.error`, and the page asks for a reload after one.
- **A hand-driven session is not byte-reproducible**, because real frame timing feeds `tick`. The same seed builds the same cluster, and the same sequence of calls and steps gives the same bytes (native tests assert this).
- **`--features embedded` tests are not part of the default `gates` nextest run**; a CI job (`wasm`) runs them, with the wasm checks.

## Future: a `WebEnv`

If a browser node that joins a real cluster is ever wanted, the path is a `WebEnv` as another instantiation of the same generic `ClientCtx<E, R>` (as `SimEnv` is), plus a relaxation or adapter for the `Send + Sync` bound, a clock policy for hidden tabs (for example, stepping a virtual clock from the page and treating the tab as a non-voting learner), and a WebSocket or fetch transport. None of that blocks or is blocked by this decision.

## Amendment 2026-10-31: the data console and the operator dashboard in the demo

**Decision.** The demo page also runs animusd's two real web UIs, the data console (ADR 0052) and the operator dashboard (ADR 0021), against the same in-tab cluster as the playground.

1. **A non-blocking HTTP API on `EmbeddedCluster`.** `submit_http(node, method, path_and_query, body)` and `poll_http(id)` route `/console/api/*` through `animus_node::console::route` (over `GenericConsoleBackend`) and `/admin/*` (not `/admin/ui/*`) through `animus_node::admin::dispatch` (over `GenericAdminHost`), the same code the real listeners call, via `SimClusterHandle::console`/`admin`. Like `submit` it spawns the request on the node's env and never blocks `advance`; a crashed node answers `503`, an unknown path `404`. `animus-web` exposes it as `Core::submit_http` and the JS method `AnimusCluster.http(node, method, path, body) -> Promise<{status, contentType, body}>`, on the same 30-virtual-second timeout pump. No wire or on-disk format is touched.
2. **Assets: one source, copied at build time.** `scripts/build-web-demo.sh` copies `console.{html,js}`, `dashboard.html`, `dashboard_*.js` from `crates/animusd/src` into `website/demo/apps/` (gitignored) and concatenates `fonts.css`, `tokens.css` and the UI's own CSS exactly as `console.rs`/`dashboard.rs` do. Exporting them from wasm with `include_str!` was rejected: it would add the fonts and every script to the wasm download for visitors who never open a UI.
3. **Same-origin iframes, no service worker.** `website/demo-frame.html` + `assets/demo-frame.js` load a UI into an iframe: inline its CSS/JS, `history.replaceState` to the UI's own path (its `location.pathname` routing works), and prepend a shim that answers `fetch` of the API paths through the parent's `window.animusDemo.http`, and turns navigations to `/console/ui/*` and `/admin/ui/*` (anchor clicks, and the console's `window.location.href =` assignments, textually rewritten to a setter) into a reload of the loader. The UI source files are otherwise unmodified. A service worker would run the UIs fully unmodified, including deep links and reload, but is unavailable in Firefox private windows and adds a root-scope registration; the iframe works wherever the playground does. Cost: reloading inside the frame is not supported (the page reloads the loader, not the UI path); use the tab.
3. **Node addressing.** The sim reports admin addresses `127.0.0.1:1` (itself) and the node ids `n0..` (peers); the shim maps a host `nK` to node K and the page's own origin to the first node that is up, so the dashboard's per-node fan-out reaches the right node and a crashed node shows as down.
4. **The clock.** UI requests made while the playground is paused run the clock at 1x until they finish, so a paused tab does not hang a UI.

**What works.** Data console: table list, table create/delete, table config, items get/scan/query/put/delete, stream shards/records, TTL. Dashboard: overview, placement, tablets, transactions, streams, data browser, storage (LSM/WAL/key inspector) and node views, cluster version, theme. **What does not, by construction:** backups, restore, PITR and export/import (no object store in a tab; they show errors or empty lists, as do the backup-store, GC and segment-store cards), index and stream `UpdateTable` (generic-dispatch gap, so the console's add/drop index fails), the metrics exporter (no collector), and the peer-console links (`target=_blank` to a node address that does not exist in a browser).

**Verification.** Native tests (`embedded::tests::console_and_admin_*`, `http_*`, `animus-web` `console_and_dashboard_requests_*`, the random-click test now issues HTTP requests); `scripts/demo-browser-smoke.mjs` opens both UIs in Chromium and Firefox (CI `demo-browsers`), lists a playground table in each and fails on any console or page error. Firefox runs only in CI.

## Amendment 2026-10-31 (2): one app shell, an embedded mode in the two UIs

**Decision.** `demo.html` stops being a long marketing page with stacked sections and iframes in bordered boxes and becomes one app shell at full viewport height. The cause was visible in use: each web UI drew its own header, logo and theme switch inside a box, the dashboard showed its "admin port, no auth" warning and refresh controls, and three menus stacked.

1. **Layout.** A single top bar (the AnimusDB logo linking home, four primary views, a few site links, the theme switch), a one-line intro with a collapsible "What's real here" panel (`<details>`; the real / simulated / not-available text moved there with its substance unchanged), the active view filling the rest of the height, and a thin **fault strip** at the bottom. The site's own header and footer are not on the page: the shell bar replaces the header (logo and links lead back to the site) and no footer sits in the app viewport. The page never scrolls; only a view's own content does, and the frames fill their area with no border. Before the first start, the view area shows a start screen (nodes, seed, Start); after it the same form moves into the Cluster view as "Rebuild".
2. **Four views, one cluster.** **Requests** (the raw DynamoDB JSON playground, the wire made visible), **Data console** (the real console), **Cluster** (the demo's own view: control leader, table/tablet/in-flight counters, node cards with Crash/Restart, Partition/Heal all, Add a node, Rebuild, the Tablets table and the Events log) and **Operator dashboard** (the real dashboard, with its own left navigation as the only nav inside it). The Cluster view is deliberately kept next to the dashboard: it is where a visitor injects faults and sees the simulator's own account of them, which the dashboard (an operator view of a running cluster) does not offer. The fault strip carries only what is needed from every view: the virtual clock, the speed slider and Pause, and one compact chip per node (up/down, control leader, a Crash/Restart toggle). Tabs are `role=tab` with arrow-key navigation; at 390 px the tab row scrolls horizontally and the strip wraps.
3. **Embedded mode in the real UIs.** `website/assets/demo-frame.js` sets `data-embedded` on the UI document's `<html>` in the shim that runs before any UI script, and copies the shell's `data-theme` onto it. When the attribute is present: `console.css` and `dashboard.css` hide the whole top bar (brand, logo, theme switch, the console's "your tables and items only" note, the dashboard's "no auth" banner, health pill and refresh controls; the elements stay in the DOM so the scripts' lookups keep working); `console.html`'s inline script and `dashboard_core.js` (`EMBEDDED`) neither read nor write their persisted theme preference (`animusd-console-theme`, `animusd-admin-theme`) and do not wire a theme switch; the dashboard's auto-refresh defaults to 2 s and polls only while the host has not set `data-embedded-hidden`; on a narrow host the dashboard's sidebar becomes a scrolling row. Without the attribute nothing changes (the new rules are all keyed on it), so the UIs `animusd` serves are byte-for-byte the same behaviour. **The shell owns the theme**: the site's key `animusdb-theme` (set by `site.js`) is the single preference; `demo.js` mirrors `data-theme` onto open frames with a `MutationObserver`, so a change propagates live. It marks which frame is showing with `data-embedded-hidden`.
4. **Fault feedback.** After a fault action the shell calls the dashboard's own global `loadAll()` (250 ms and 1.5 s later, only while the dashboard view is showing), and again when the dashboard view is opened; the 2 s embedded poll covers the rest. A hidden dashboard does not poll, so a paused clock stays paused (UI requests from a visible view still advance it at 1x, as in the first amendment).
5. **De-duplication.** Removed: the page-level hero and "What this is, and is not" sections, the "Talk to the cluster" explanation and the per-tab blurbs, the doubled brand/theme/header chrome inside the frames, the dashboard's warning and refresh controls, and the standalone clock/speed row (the strip is the only copy). Kept on purpose: the Requests playground (it shows the JSON wire, and its examples are wire-level, not shortcuts into the console), and the Cluster view's node cards beside the strip's chips (cards show detail, chips are the always-reachable toggle).

**Verification.** `scripts/demo-browser-smoke.mjs` (Chromium locally, Firefox in CI) drives the four views, asserts the frames show no logo, header, theme switch or warning, that the shell's theme change reaches an open frame, that a crash from the strip shows up in the dashboard without a manual refresh, that the page does not scroll in any view (including at 390 px, dark mode) and that pause still holds the clock with the dashboard loaded. The animusd asset tests are unchanged.
